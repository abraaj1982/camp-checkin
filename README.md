# 🏕️ MUKHAYYAM — منصة إدارة المخيم الطلابي

منصة ويب عربية/إنجليزية لإدارة مخيم طلابي (نحو 300 طالب): تسجيل صعود الحافلات بسوار QR، وتتبع الباصات، وتسجيل الأغراض، وإدارة المستخدمين والصلاحيات، وتقارير للقيادة. تعمل بلا تكلفة اشتراكات: **GitHub Pages** للواجهة، و**Google Apps Script** للخادم، و**Google Sheets** كقاعدة بيانات.

> **المخيم:** 27 ديسمبر 2026. الحالة العامة: قيد البناء بحسب الجدول في [خريطة الطريق](#-خريطة-الطريق).

---

## 🧭 الفكرة

1. أولياء الأمور يسجّلون بيانات أبنائهم في نموذج يغذّي **Google Sheet**، وهو قاعدة البيانات.
2. يُوزَّع الطلاب على الفرق والحافلات، ويُطبع لكل طالب **سوار QR** بلون فريقه.
3. يوم الوصول يمسح مشرف كل باص السوار (أو يبحث بالاسم أو الرقم)، فيُسجَّل صعوده ولا يتكرر.
4. القائد يتابع الأرقام والباصات مباشرة على الخريطة.
5. لكل شخص حساب (يوزر وباسورد)، ولا يرى إلا الشاشات التي تخصه.

## 👥 الأدوار والصلاحيات

لكل مستخدم **قائمة صلاحيات** (علامات اختيار) تحدّد ما يظهر له. الدور القديم قالب يُستخدم إن كانت القائمة فارغة، و**الأدمن** يملك كل شيء دائماً.

| المفتاح | ما يفتحه |
|---|---|
| `checkin` | شاشة المشرف (يسجّل لباصه المخصَّص فقط) |
| `allbuses` | تسجيل لأي باص |
| `dashboard` / `stats` / `livemap` | شاشة القائد |
| `print` | طباعة الأساور والكشوف |
| `custody` | شاشة الأمانات والانسحاب المبكر |
| `manage` | إنشاء الحسابات وتعديل الصلاحيات |
| `support` | إعادة كلمة المرور وفك القفل فقط (لا يلمس الحسابات الإدارية) |
| `shirts`, `committee`, `results`, `medical`, `verify`, `announce` … | شاشات قادمة |

الكتالوج الكامل في تبويب `PermissionsCatalog` بالشيت، فإضافة صلاحية = إضافة صف.

## 🔐 الأمان والخصوصية

- **لا توجد نقاط قراءة عامة.** كل طلب بيانات يمر عبر `POST` مع توكن، والخادم يعيد قراءة صف المستخدم في كل طلب (فتغيير الصلاحيات يسري فوراً).
- **كلمات المرور** تُخزَّن مشفّرة (PBKDF2-HMAC-SHA256 بملح فريد)، ولا يمكن استرجاعها. قفل الحساب بعد 5 محاولات خاطئة لـ 15 دقيقة، وانتهاء الجلسة بعد 30 دقيقة خمول و3 ساعات مطلقة.
- **التوكن** في `sessionStorage` فقط، ولا يظهر في أي رابط.
- **قيد الباص في الخادم:** باص الطالب يُؤخذ من الشيت لا من الجهاز. المشرف يطّلع على بيانات الباصات الأخرى دون أن يسجّل لها.
- **منع التكرار والتراجع** في الخادم، مع قفل (`LockService`) لمنع تعارض مشرفَين، ومفتاح `clientId` يجعل إعادة الإرسال آمنة.
- **لا أرقام جوالات** في أي استجابة للمشرف أو القائد أو الطباعة.
- **سجل تدقيق** (`AuditLog`) للعمليات الحساسة.
- **بيانات القاصرين:** هذا المستودع **عام**، فلا تُرفع إليه أي بيانات حقيقية (أسماء، صور، جوالات، حالات صحية، أو معرّفات شيتات). أسماء الطلاب والمشرفين في الأمثلة والاختبارات أسماء تمثيلية فقط.
- **الصور** (للتعرف على الوجه لاحقاً): بموافقة صريحة من ولي الأمر، وفي مكان خاص، وتُحذف بعد المخيم.

## 🏗️ المعمارية

```
المتصفح (GitHub Pages)  ──POST + توكن──▶  Google Apps Script (server/)  ──▶  Google Sheets
  login · hub · supervisor                   Auth.gs  (دخول، توكن، صلاحيات)       ├─ شيت المنصة: Users, Settings,
  leader · wristbands                        Code.gs  (الصعود، الأغراض، الباصات)   │   AuditLog, Committees,
                                                                                   │   PermissionsCatalog, Scans,
                                                                                   │   Bags, BusLive
                                                                                   └─ شيت الطلاب (قابل للتبديل): Bus
```

- **شيت الطلاب قابل للتبديل** دون تعديل كود: غيّر `ActiveStudentSheetId` في تبويب `Settings`. تُقرأ الأعمدة **بأسمائها** لا بترتيبها.
- **السجلات في شيت المنصة** (لا في شيت الطلاب)، فلا تضيع عند تبديله.
- يُحدَّث الخادم بـ **Manage deployments ← New version** على النشر نفسه، فيبقى الرابط.

### أعمدة تبويب `Bus` (شيت الطلاب)
| العمود | مطلوب؟ | ملاحظة |
|---|---|---|
| `Student ID` | ✅ | رقم الطالب (يُشفَّر في QR بصيغة `MKH:<id>`) |
| `Name` | ✅ | |
| `Bus number` | ✅ | |
| `Team name` | مستحسن | للأساور |
| `Class` | اختياري | |
| `Photo URL` | اختياري | للتعرف على الوجه لاحقاً |
| `Bags` | اختياري | عدد الحقائب المتوقع |
| `Contact number` | اختياري | **لا يُرسَل إلى الواجهة** |

أسماء بديلة (عربية وأخرى) معرَّفة في `STUDENT_HEADERS_` داخل `server/Code.gs`. زر «فحص شيت الطلاب» في `hub.html` يكتشف عموداً ناقصاً أو رقماً مكرراً أو طالباً بلا باص.

## 🚀 الإعداد والنشر

> جرّب دائماً على **نسخة اختبار** (شيت منفصل وسكربت منفصل) قبل الإنتاج. التفاصيل والسيناريوهات في [`docs/week2-handoff.md`](docs/week2-handoff.md).

1. **الشيت:** أنشئ شيت المنصة (أو انسخ الحالي). تبويب `Settings` فيه `ActiveStudentSheetId`.
2. **الخادم:** من الشيت: *Extensions ← Apps Script*. أنشئ ثلاثة ملفات والصق `server/Auth.gs` و`server/Code.gs` و`server/Custody.gs` كاملة، واستبدل `SHEET_ID` في `Code.gs` بمعرّف شيت المنصة.
3. شغّل الدالة **`SETUP_createTabs`** مرة واحدة (تنشئ التبويبات الناقصة ولا تمسح شيئاً، ويمكن تشغيلها مرات).
4. **Deploy ← Web app** (Execute as: Me · Access: Anyone). انسخ رابط `/exec` وضعه في `APPS_SCRIPT_URL` داخل كل صفحة html.
5. **أول مدير:** يُنشأ مرة واحدة بسر البدء (`ADMIN_printBootstrapSecret`) عبر `createUser`، ثم يُنشئ بقية الحسابات من `hub.html`.
6. **الواجهة:** فعّل GitHub Pages من الفرع `main`.

### التراجع
*Manage deployments ← اختر النسخة السابقة ← Deploy*. وخذ **نسخة من الشيت** (ملف ← إنشاء نسخة) قبل أي تحديث.
